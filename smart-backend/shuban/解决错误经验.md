# 书版 Word 转 FBD 错误处理经验

本文记录 `shuban` 工作台的 Word→FBD 转换问题、原因和当前处理方式。涉及公式或特殊符号时，先读源文档上下文，再添加显式映射；不要对整篇文档做盲目 Unicode 归一化或静默删字。

## GBK 字符无法编码

### 现象

转换器报告“Word 中包含无法写入 FBD 的字符”，并列出字符及 Unicode 码位，例如 `U+200A`、`U+2245`、`U+2A7D`。这表示 DOCX 中的 Unicode 字符无法直接写入 GBK 编码的 FBD，不代表 Word 文件损坏。

### 已确认映射

`tools/docx_to_series_fbd.py` 的 `SYMBOL_MAP` 维护经过上下文确认的替代规则：

| Word 字符或类别 | FBD 写法 | 备注 |
| --- | --- | --- |
| `⇨`、`⇒`、`⟶`、`⟹`、`➝` | `→` | 箭头含义适配的场景 |
| `−` | `－` | 数学减号 |
| `∘` | `°` | 已确认用于角度值时 |
| `∼` | `∽` | 几何相似关系 |
| `≅` | `≌` | 已确认用于三角形全等时 |
| `⩽` | `≤` | 小于等于关系 |
| `⋅`、`•` | `·` | 点乘或标题分隔点，需看上下文 |
| `⋯` | `…` | 数列省略号 |
| `∗` | `＊` | 用户定义运算符，保留与普通乘号的区别 |
| `⊗` | `⊕` | 仅用于已定义的自定义运算符，并经人工确认；字形会变化，当前核对报告不会单独列出该映射 |
| `▱` | `平行四边形` | 几何标记用文字保留含义 |
| `U+2009`、`U+200A` | 普通空格 | Word 的窄空格 |
| `U+2060` | 删除 | Word Joiner 不可见且不承载文本内容 |

上下标和圈码不是普通字符替换：

- 字面下标 `₂`、`₄`、`₅` 输出为 FBD 下标控制符 `AD` 加数字；内容核对时用普通数字比较。
- 圈码 `⑪`、`⑫` 输出为 `A1 / B21 / A3`、`A1 / B22 / A3`；内容核对使用对应圈码编号。
- OMML 数学脚标优先按公式树结构转换；不要把上下标控制符直接替换为普通数字，否则会改变版面。

### 未知字符

已知映射表之外的不可编码字符不会导致整份排版立即中止。生成器会在 FBD 中用 `□` 占位，并将原字符、码位、出现次数和最多 5 个小样段落位置写入 `转换核对.json` 和 ZIP 中的 `转换问题说明.txt`。前端显示告警，`contentVerified` 应为未通过。用户修正占位符或补充经过确认的映射前，结果不能作为可直接发排的最终稿。

内容映射与输出映射分开维护：`CONTENT_SYMBOL_MAP` 只规范内容核对值，`SYMBOL_MAP` 决定实际 FBD 标记。新增规则时应确保两边匹配，避免格式控制符被误判为文字差异。

## OMML 公式属性缺失

Word 的 OMML 分隔符 `m:d` 可以没有 `m:dPr`。若解析器对缺失节点直接调用 `.find()`，会报 `AttributeError: 'NoneType' object has no attribute 'find'`。`omml_to_fbd()` 的 `child()` 现在接受空父节点；缺少括号属性时使用默认圆括号。

修改 OMML 解析时，把可选属性视为可缺省，并为公式分子、分母、上下标和定界符保留默认行为。

## FL 分栏错误

### 嵌套错

FL 开栏包住一段分栏内容；上一段未闭合前不能再次开栏。旧问题由把整份正文模板（包含样例内容和 FL 开栏）当作模板版头传入造成，随后生成器又追加开栏。正文模板现在只截取首个 FL 开栏前的版头字节；夹册使用专门的版头行区间，避免把样例标题带进新文档。

### 开弧或多余闭栏

正文卷尾曾由 `VOL_CLOSE` 和公共 `FILE_TAIL` 各关闭一次，导致同一分栏重复闭合。最终文件尾由公共 `FILE_TAIL` 负责关闭；只有切换到下一卷时才使用 `VOL_CLOSE`。

转换后会按 FL token 的顺序检查嵌套开栏、无对应开栏的闭栏和未闭合开栏。此类问题作为告警写入界面和 `转换问题说明.txt`；生成结果可供检查，但应先修正再正式发排。

## Windows 上传覆盖失败

### 现象

`POST /api/shuban/upload` 返回 500，后端堆栈指向 `os.replace(temp, destination)`，错误为 `PermissionError: [WinError 5]`。常见于重复导入已存在的 FBD/PRO/图片，或 ZIP 再次包含已有模板素材；这不是文件大小限制或 FBD 解析错误。

### 处理

- multipart 文件名在部分 Windows 客户端/字符集组合下会变成 CP437 或 Latin-1 乱码。`_upload_filename()` 只在解码结果确实包含中文时恢复文件名，避免新建乱码路径。
- `_same_file_contents()` 比较同路径已有文件；内容相同则跳过覆盖，重复导入按成功处理。
- `_replace_uploaded_file()` 捕获 Windows `PermissionError` 并返回 409，提示关闭占用文件的程序或移走同名旧文件，不再将操作系统堆栈作为 500 返回。
- ZIP 解压也复用相同文件处理逻辑。不要为了覆盖失败而静默删除已有文件；若文件确实被其他程序锁定或 ACL 禁止修改，应由用户关闭占用程序或处理旧文件后重试。

## 内容与结构校验

- 每次生成调用 `fbdgen.validate()`，检查控制符、注解开闭、GBK 字节、CRLF 和文件结束符。
- `math_content_report()` 将 Word 可见文本与 FBD 可见文本规范化后逐字符比较；占位符、丢字或错误映射应使核对失败。
- `aaab` 等来自模板宏的未知用户区字节会附带已知说明；不能仅因浏览器可预览就判定书版发排通过。
- 浏览器结果是近似排版，最终分页和发排效果以方正书版实际发排为准。

## 上传限制

- 普通 FBD、PRO、ZIP、图片和 DOCX 单个上传文件上限为 500 MB。
- ZIP 内部单个可导入文件仍限制为 50 MB，最多 1000 个文件，解压总量最多 512 MB。
- DOCX 是 ZIP 容器：最多 2000 个条目，单条目最多 100 MB，解包后总量最多 512 MB。
- 无效 DOCX、超限、模板或转换器缺失等致命错误会返回 API 错误并清理本次临时目录；可恢复的字符与结构问题会生成带告警的预览和 ZIP。

## 结果包

成功的 Word 转换 ZIP 包含 FBD、配套 PRO、实际引用的 TIFF/EPS 素材、`preview.html`、`转换核对.json`、`转换问题说明.txt` 和排版说明。原始 DOCX 不放入结果 ZIP。若有 `□` 占位符，必须先根据 TXT 中的位置修正，再重新转换和核对。
