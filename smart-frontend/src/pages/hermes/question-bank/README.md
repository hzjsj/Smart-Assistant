# Hermes 题库组卷

本功能的代码、测试及说明仅位于前端 src/pages/hermes 和后端 hermes 内。

## 使用

默认保持原对话布局。智能组卷生成题库后，回复中的 question-bank 专用块显示为 300px 宽的文件卡片（窄屏自适应）：顶部文件名，描述栏左侧为学科、年级和题数，右侧为“查看题目”，不提供题库 JSON 下载按钮。点击卡片或“查看题目”才打开 Splitter，桌面默认左侧对话 40%、右侧题库工作台 60%，双击分隔条恢复该比例，自动隐藏导航；顶部可展开导航或返回完整对话。聊天组件不会因开关分屏而重新挂载，草稿和 SSE 请求保持。窄屏使用题目抽屉。

题库加载成功后默认全选，可按题型查看、单题/全选、显示答案解析。题目区顶部只保留一行工具栏：左侧为“全选”和“显示答案和解析”，右侧为学科、年级和实际题数；不显示标题行及面板关闭按钮，可通过工作台顶部“返回完整对话”收起。点击“组卷预览”保存当前选择的快照，沿用题库标题，再按同一快照下载 Word、PDF、Excel 双向细目表及 JSON。缺失分值显示“未标注”，不以题数代替总分。

原全局“题库组卷工作台”标题改为右侧分栏自身顶部的实际题库标题，与题目内容左边缘对齐并随分隔条拖动。点击标题进入编辑，Enter 确认（中文输入法组词确认不触发保存），Esc 或失焦取消；空标题不可保存。确认后的标题在当前会话题库缓存中保留，后续创建的试卷快照和导出使用该标题；已保存的快照不变。手机端在题库抽屉标题处编辑。

组卷预览从右侧抽屉打开，桌面默认宽度 60%、支持拖动调宽，窄屏为全宽。顶部最左侧为“打印预览”，然后为四种导出操作；正文独立滚动，布局与色调参考 generate-test-paper：白底试卷、黑灰标题和说明、蓝色 PDF 主按钮。试卷题数和分值来自快照，不复制参考页面的假设分值或固定考试时间。打印在独立窗口打开同一快照，复制样式、等待字体及图片就绪后调用浏览器打印，不包含对话、工具栏或未选题目。

题号与题干首行同行，长题干在题号右侧自然换行；单题旁不再单独显示分值。列表和预览的题型标题使用“一、选择题（本大题共8小题，每小题4分，满分32分）”格式。各题分值不同时改为“各小题分值不等，满分…分”；缺失分值时显示“部分小题未标注分值”，不编造每题或总分。列表汇总整份题库，预览/打印/PDF/Word 按选题快照重新汇总。

同一会话重复打开同一卡片会保留选题；切换题库分别保存当前页状态。加载新题库失败时保留旧题目并提供重试。未保存状态只保留于当前页面内存；已组卷快照与已导入题库由后端持久化。

工作台开关采用 280ms 过渡，导航占位和分栏同时变化。展示宽度直接使用百分比 CSS，避免 Splitter 的容器测量落后一帧产生二次跳变；拖动时不加尺寸过渡。右侧内容在展开过程中按目标宽度排版并裁切显现，避免从零宽度开始反复换行；加载与完成复用同一行工具栏，滚动区域预留滚动条空间。关闭后恢复原导航状态，草稿与选题不重新挂载；快速开关会取消旧的结束定时器，系统减少动态效果时立即切换。

动画验证：`node src/pages/hermes/question-bank/tests/workspace-motion.e2e.cjs`。模拟接口延迟 500ms，记录首次打开与缓存重开的逐帧位置；覆盖宽度单向展开、加载前后工具栏高度不变、原编辑器与选择保留、拖动、快速反向操作及减少动态效果。逐帧数据保存在已忽略的 `.artifacts/workspace-motion-*.json`。

## 对话协议

普通正文为简短 Markdown；完整题目放在实际发布的 JSON 文件中。工具执行步骤继续使用上游真实 SSE 事件。

只有点击组卷表单的“生成试卷”才提交 `task="question_bank"` 和 `paper_config`（subject、grade、knowledge_points、question_types、quantity、difficulty、exam_type、remarks）；表单选择变化不发起聊天。用户气泡只展示所选内容，完整题库协议由后端注入该次请求，既不存入前端对话历史，也不在后续提问中重复注入。同一会话后续提问和其他新建对话均为 `task="chat"`，不携带组卷参数。

表单快照保存在原用户消息中。重新生成原组卷回复时复用该快照和该回复之前的历史，排除后续消息；重新生成普通回复仍为普通聊天。快照仅用于原请求的重试，不作为整个会话的永久模式。数量范围 1～50，难度为 1～10 整数，备注最多 4000 字；未指定题型和知识点的安排由后端决定。

回复卡片采用专用 fenced 块：

```question-bank
{"type":"question_bank","version":1,"id":"实际题库id","name":"实际题库.json","url":"https://实际允许源站/实际文件.json","question_count":30,"subject":"数学","grade":"初中一年级","exam_type":"单元测试","difficulty":5}
```

上述 URL 为协议说明，不可作为生成结果返回。实际文件根字段：type、version、id、title、subject、grade、exam_type、difficulty、questions。每题字段：id、type、content、options(label/content)、answer、analysis、score、knowledge_points、cognitive_level、difficulty。JSON 的 LaTeX 反斜杠需转义。

元信息块从显示层逐字队列中移除，原始回复仍保存在 useXChat 中用于上下文。未闭合块显示等待；SSE 已结束但块仍不完整时显示错误。普通 JSON 代码块不会成为题库卡片，普通 .json 附件只下载；只有有效的专用协议卡片能打开题目面板。

## 文件与接口

- 题库导入、校验、JSON 下载：/api/hermes/v1/question-banks/*。
- 已选题目快照与文件：/api/hermes/v1/papers/_、/api/hermes/v1/exports/_。
- 所有请求沿用当前站点登录态；跨源文件由后端受控导入，不由浏览器直接请求。
- Word 由已有 Pandoc 生成，公式为原生 OMML；Excel 使用后端标准库输出真正的 xlsx，两张工作表为“题目明细”和“维度汇总”。
- PDF 使用已有 html2pdf.js 和预览中的 KaTeX/中文排版生成，再上传到所属试卷接口校验并保存；不依赖本机未安装的 LibreOffice。PDF 本身是浏览器栅格渲染，Word 保留可编辑公式。
- 同一个已保存快照用于所有导出；再次组卷会创建新快照，避免文件内容与修改后的选题混淆。

## 检查

单元测试均在本目录及上层 Hermes 目录。现有 Umi Jest 的 setupFiles 初始化次序需在命令中移动 jest-dom 到 setupFilesAfterEnv：

```powershell
npm test -- --setupFiles=./tests/__mocks__/raw.js --setupFilesAfterEnv=./tests/setupTests.jsx --runInBand --testPathPatterns=src/pages/hermes
```

浏览器集成测试使用隔离的 SQLite 和模拟上游（不调用真实模型，也不绕过正式服务鉴权）：

1. 后端启动 venv/Scripts/python.exe -m uvicorn hermes.tests.serve_workspace:app --host 127.0.0.1 --port 6061。
2. 保持前端 8002 端口开发服务运行。
3. 在前端根运行 node src/pages/hermes/question-bank/tests/workspace.e2e.cjs。

测试生成的截图、PDF/Word/Excel 均放在 Hermes 内 .artifacts，已在目录内忽略。集成测试核对默认布局、点击分屏、导航开关、草稿/选题保留、实际分值、四种文件下载和手机宽度。

本轮 Hermes 前端 11 个测试套件共 72 项通过；后端沿用此前 21 项验证基线，本轮未修改后端代码。浏览器使用隔离模拟上游，验证表单编辑不发送请求、提交后只显示摘要、同一会话追问保留历史且不携带组卷配置、原回复重试仅使用原快照和原历史、新建普通对话不注入题库协议，并核对上游仅收到标准聊天字段。另实测 1440px 视口下对话 576px / 题库 864px（40% / 60%）、390px 视口无横向溢出、题号题干同行及题型真实分值汇总、标题编辑与拖拽对齐。打印测试拦截 print 调用核对选题快照，四种文件实际下载成功，关闭/重开保留草稿和勾选。组件检查、目录内 Biome 及 tsc --declaration false 通过；默认全量类型检查仍可能遇到目录外 .umi/plugin-access/index.tsx 的 TS2883 生成类型问题。此验证不代表对真实模型题目正确性的验收。
